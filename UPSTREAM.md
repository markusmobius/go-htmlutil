# Upstream Compatibility

Behavioral authority: python-dateutil **2.9.0.post0** under CPython **3.14.6**.
The Go compatibility version is **2.9.0**, using module path
`github.com/markusmobius/go-dateutil/v2`. This release implements only the
documented parser and relative-arithmetic subset, not the complete upstream API.
Upstream tag `2.9.0.post0` resolves to commit
`1ae807774053c071acc9e7d3d27778fba0a7773e`.

## Source Mapping

| Python source | Go implementation | Supported consumer behavior |
| --- | --- | --- |
| `dateutil/parser/_parser.py`: `_timelex` | `parser/lexer.go` | Python Unicode tokenization |
| `_ymd`, `parserinfo`, `parser._parse`, `parser._build_naive`, `parser._build_tzaware` | `parser/dateutil.go` | Default English, `fuzzy=False`, no custom `tzinfos` |
| `dateutil/relativedelta.py`: relative constructor fields, `_fix`, datetime addition | `relativedelta/relativedelta.go` | Relative units used by DateParser |

Source SHA-256 pins:

- `_parser.py`: `ee494377289c92c401fd7825fb7500981c33098a2bd40219aa4948713e9d1fff`
- `relativedelta.py`: `218fe6825323a196d87ebbe5a1363671ed366a25633c892265faa03536517ee0`
- Unicode character properties: CPython 3.14.6 / Unicode 16.0.0, generated by
  `str.isalpha`, `str.isdigit`, `str.isspace`, and `unicodedata.decimal`.
- Reference timezone data: `tzdata==2026.3`.

Parser input cases were initially extracted from the Go HtmlDate comparison
corpus and supplemented with direct parser edge cases. All expected token
streams, datetimes, and rejections come from Python, never from Go or Rust.
ISO-parser expectations have been removed: CPython ISO parsing belongs to a
separate compatibility surface.

## API Boundaries

The caller provides a default datetime and parser initialization year separately,
matching Python's distinct default-clock and `parserinfo` year semantics.
Results expose offset awareness separately because Go times always have a
location. Python errors become Go errors; Python warning delivery and exception
wording are not reproduced. Unknown dateutil timezone names retain naive parsing
rather than being assigned invented offsets.

Relative arithmetic always clamps month ends. Go-DateParser's previous optional
`PreserveEndOfMonth` behavior must not change this package's Python semantics.
For an imaginary local wall time in a DST gap, Go cannot represent the wall
fields with the original IANA location; the result uses a fixed offset preserving
Python's wall fields and offset. Ordinary and ambiguous valid times retain the
location. This is a representation limitation, not an elapsed-time substitution.

The complete upstream test suite includes unsupported APIs and is not a claimed
gate. The selected API contract is tested independently and must stay stable.
Upstream upgrades require an explicit source-pin change, regenerated Python
outputs, reviewed differences, and consumer tests. A passing corpus is not proof
of universal equivalence outside the supported API contract.

## v2.9.0 Verification

The packaged tests compare 3,273 lexer results, 3,273 parser results, and
146 relative-arithmetic results with independently generated Python expectations.
They passed as a standalone module (`GOWORK=off`) on Linux with Go 1.26.0 and
1.27.1, and natively on Windows with Go 1.27.1. Linux race tests, `go vet`,
module tidiness, and pinned-Python fixture regeneration also passed. Regeneration
checked both fixtures and the Python Unicode tables byte-for-byte.

The [test workflow](.github/workflows/test.yml) runs the offline tests, vet,
and module-tidiness check on Linux and Windows with minimum and stable Go.
Python is needed only to regenerate or independently recheck the saved oracle,
not to use the library or run its regular tests.
